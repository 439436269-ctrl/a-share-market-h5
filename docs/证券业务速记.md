# 证券业务速记卡

> 面向「大前端 + 证券 / 行情 / 交易」岗位。目标不是成为业务专家，而是**能听懂、能对话、能提出正确的问题**。
> ⚠️ 规则类内容随监管与交易所规则调整，面试时如被追问细节，以"我了解到的是……具体我会去查最新的交易所规则文档"收口，比硬答错强。

## 一、交易时段与状态机（必会，最容易被问）

| 时间 | 阶段 | 关键约束 |
|---|---|---|
| 09:15 – 09:20 | 集合竞价（第一段） | **可申报、可撤单** |
| 09:20 – 09:25 | 集合竞价（第二段） | **可申报、不可撤单** |
| 09:25 | 产生开盘价 | —— |
| 09:25 – 09:30 | 接收申报，不撮合 | 交易所接收委托但不成交 |
| 09:30 – 11:30 | 连续竞价（上午） | 价格笼子生效 |
| 11:30 – 13:00 | 午间休市 | **分时图 x 轴不占位**（这是分时图的核心约定） |
| 13:00 – 14:57 | 连续竞价（下午） | —— |
| 14:57 – 15:00 | 收盘集合竞价 | **不可撤单** |
| 15:00 | 收盘 | —— |

**前端必须从中得出三条结论**：
1. **不能本地判断交易时段** —— 有时区、节假日、临时休市、半日市，必须由服务端下发状态机。
2. **撤单按钮的可用性依赖竞价子阶段** —— 09:20 之后撤单按钮必须禁用，这个细节很多产品会漏。
3. **分时图 x 轴是"交易分钟序号"**：09:30 是 0，11:30 是 119，**13:00 是 120**，午休不占位。

## 二、涨跌停与价格笼子

| 板块 | 涨跌停幅度 |
|---|---|
| 主板 | ±10% |
| 主板 ST / *ST | ±5% |
| 创业板 / 科创板 | ±20% |
| 北交所 | ±30% |
| 指数 | 无涨跌停 |
| 注册制新股 | 上市**前 5 个交易日不设涨跌幅**，之后按所属板块 |

**计算方式**：涨跌停价 = 昨收 × (1 ± 幅度)，**四舍五入到分**。注意基准是**经过除权处理的昨收**，不是昨天的原始收盘价。

**价格笼子**：连续竞价阶段的限价申报有有效价格范围限制（主板 / 创业板 / 科创板目前均设 2% 级别约束，如买入不高于基准价 ×102%、卖出不低于 ×98%）。前端做下单校验时必须带上这一层，否则用户会收到"废单"却不知道为什么。

**申报单位**：主板 100 股起、100 股整数倍递增；零股卖出必须一次性卖出。科创板限价申报 200 股起、可 1 股递增。

> **盘口业务语义（面试加分）**：封涨停时**卖盘为空、买一巨量排队**；封跌停反之。这不是"数据缺失"，显示 `--` 是正确表达，补 0 是错的。

## 三、订单类型（沪深不一样，这是跨市场适配的重点）

| 类型 | 说明 |
|---|---|
| 限价单 | 指定价格 |
| 对手方最优价格 | 以对手方最优价成交（沪、深都有） |
| 本方最优价格 | 以本方最优价挂单（沪、深都有） |
| 最优五档即时成交剩余撤销 | 吃五档，剩余撤掉（沪、深都有） |
| 最优五档即时成交剩余转限价 | 吃五档，剩余转限价挂单（**沪市特有**） |
| 即时成交剩余撤销 | **深市特有** |
| 全额成交或撤销 | **深市特有** |

> 做交易页面时，"市价单"在沪深两市的实现语义不同，**必须按市场分别配置可选项**，否则会出现用户选了"市价"但报单被拒。

**费用**：佣金（券商收，双向）、印花税（**卖出单边 0.05%**，2023-08 起减半）、过户费（沪深双向收取）。

**交收**：A 股 T+1 交收（股票 T+1 可卖、资金 T+0 可用 T+1 可取）；港股 T+2；美股 T+1。

## 四、行情数据：分级与形态（"行情"这条的核心）

### 分级

| 级别 | 数据形态 | 用途 |
|---|---|---|
| **Level-1** | 3 秒级快照 + 五档盘口 | 免费行情、普通用户 |
| **Level-2** | 十档盘口、逐笔成交、逐笔委托（深市）、委托队列、毫秒级快照 | 付费行情、专业用户 |

### 四种基础数据形态

| 形态 | 字段 | 说明 |
|---|---|---|
| **Snapshot（快照）** | 最新价、开高低收、成交量额、五档/十档量价、时间戳 | 行情 UI 的主力数据 |
| **Tick / 逐笔成交** | 价、量、**主动方向**、成交编号、时间戳 | 成交明细；方向由交易所给出，**不能靠价格比较猜** |
| **Order / 逐笔委托** | 订单号、价、量、买卖方向、订单类型 | 深市 L2 提供 |
| **OrderBook（订单簿）** | 由逐笔委托 + 逐笔成交重建的买卖队列 | 盘口重建，L2 的核心价值 |

### 协议与传输（面试加分项）

- **交易所侧**：私有二进制协议；港交所 OMD（OMD-C 证券 / OMD-D 衍生品）用 **FAST 协议**压缩；美股 Nasdaq 用 **ITCH**（逐笔行情）/ **OUCH**（下单）；行业通用 **FIX** 协议
- **互联网侧**：WebSocket / TCP 长连接 + Protobuf 自定义二进制 / SSE / HTTP 轮询（降级）
- **关键机制**：全量快照 + 增量推送、**序列号缺口检测与补拉**、心跳保活、指数退避重连、订阅合并与按需订阅、压缩（gzip / brotli / zstd）、服务端时间对齐

### 一致性难题（高级问题）

| 问题 | 表现 | 对策 |
|---|---|---|
| 丢包 | 盘口永久错位 | seq 校验 + 定期全量刷新 |
| 乱序 | 时间倒流的 tick | 按 seq / 时间戳排序，丢弃旧帧 |
| 跨市场 | 时区、交易时段不同 | 统一为 UTC 存储、展示层转换 |
| 除权除息 | 价格跳空 | 涨跌幅基准用**除权后的昨收** |
| 停牌 / 熔断 | 数据静止但连接正常 | 状态字段显式下发，UI 明确展示 |

## 五、K 线与指标

- **周期**：1m / 5m / 15m / 30m / 60m / 日 / 周 / 月
- **生成方式**：逐笔 → 1 分钟 bar（**归并/upsert，不是追加**）→ 更高周期（**读时聚合**，避免多份数据不一致）
- **复权**：
  - **前复权**：以最新价为基准往前调整历史价 —— 看走势连续性
  - **后复权**：以上市首日为基准往后调整 —— 算真实收益率
  - **不复权**：真实历史成交价 —— 看真实成交
  - 本质都是用**复权因子**修正除权除息造成的跳空
- **常用指标**：MA / EMA、MACD、KDJ、BOLL、RSI、量比、换手率、振幅、委比

## 六、交易链路与订单状态机

```
登录鉴权 → 资金/持仓查询 → 下单 → 风控校验 → 报盘 → 交易所撮合
                                                      ↓
              ┌─────────── 回报推送（WS / 长轮询）───────────┐
              ↓                                              ↓
       委托列表实时刷新                                成交回报 → 持仓/资金更新
```

**订单状态**：待报 → 已报 → 部成 → 已成 / 已撤 / 废单

**前端必须处理的**：
1. **幂等**：客户端生成订单号，重试复用同一个，服务端按它去重
2. **超时不算失败**：先查单确认状态，不盲目重发
3. **风控前置**：可用资金、可卖数量、价格笼子、涨跌停 —— 本地先校验一遍，减少废单
4. **二次确认**：确认框里必须带全参数（方向、价格、数量、金额）
5. **回报实时推送**：委托/成交列表高频刷新，注意同样是"局部更新"问题

## 八、8 道高频业务题 · 速答

1. **集合竞价阶段 UI 怎么处理？**
   展示虚拟开盘价与匹配量；09:20 后撤单入口必须禁用；明确标注"集合竞价"状态，不能让用户以为价格已经成交。

2. **五档盘口的价格按什么着色？**
   按**与昨收比较**（高于昨收红、低于绿），不是按买卖方向。这是国内行情软件的既定习惯。

3. **为什么不能本地判断交易时段？**
   时区、节假日、临时休市、半日市都会让本地判断出错。必须服务端下发状态机，前端只做展示与禁用。

4. **为什么涨跌幅不能只显示一个百分比？**
   不同板块幅度不同（10% / 20% / 30% / 无），还要表达"是否封板"（涨停/跌停/一字板）。派生字段必须能互相解释。

5. **逐笔成交怎么判断主动买卖？**
   用交易所给出的方向字段。**不能靠"价格比上一笔高就是主动买"来猜** —— 集合竞价的成交方向是中性。

6. **K 线切换周期为什么要重新请求？**
   因为聚合在服务端做（读时聚合）。若本地聚合，必须保证与后端完全相同的分钟对齐与边界处理，否则同一只票两个页面显示不一致。

7. **行情断线时 UI 应该怎么表现？**
   状态条明确切到"重连中/补拉中"，并始终展示数据时间戳。**绝不能让用户以为看到的是实时价** —— 这是行情产品最严重的体验事故。

8. **交易页按钮什么时候禁用？**
   非交易时段、涨跌停方向的不可成交、资金/持仓不足、风控拦截。每一条都要给出**具体原因文案**，不能只是置灰。
